    данные и интеграция

    Интеграционные паттерны - Синхронная vs асинхронная коммуникация - Паттерны отказоустойчивости - Практика: проектирование отказоустойчивой системы

    Тема: архитектура данных, ETL/ELT, репликация, sharding, CAP, ACID vs BASE, message brokers (RabbitMQ/Kafka), API gateway, REST vs gRPC, контрактное тестирование.

    Что делать: реализовать простую event-driven интеграцию: сервис A публикует события в Kafka → сервис B обрабатывает.

    Результат: диаграмма потоков данных + метрики задержки/пропускной способности.

    Финалочка

    Проект 1: перевод простого монолита в микросервисы (микро-миграция) — план + PoC.

    Проект 2: проектирование enterprise-системы (диаграммы C4, ADR, нефункц. требования, cost/benefit).

    Результат: готовое портфолио: architecture doc + диаграммы + ссылки на репозитории.

    Для улублённого изучения:

    1. Single Node Storage (Storage, Index, Concurrency Control, Recovery)
    2. Replication
    3. Sharding/Partitioning
    4. Consistency, Consensus
    5. Networking
    6. Observability, Discovery
    7. Architecture Patterns

    Ключевые артефакты, которые нужно научиться делать

    C4-диаграммы уровней (System Context, Container, Component, Code).

    Architecture Decision Records (ADR) — формализованные решения.

    Нефункциональные требования (performance, scalability, availability, security).

    Инфраструктура как код (Terraform, k8s manifests).

    CI/CD pipeline + тесты (unit, integration, contract).

    Мониторинг/алертинг + SLOs.

    Инструменты и технологии для практики

    Языки/фреймворки: любое знакомое (Node/Python/Java/C#).

    БД: PostgreSQL, Redis.

    Message brokers: RabbitMQ, Kafka (по желанию).

    Контейнеры/оркестрация: Docker, Kubernetes (minikube/k3s).

    CI/CD: GitHub Actions / GitLab CI.

    IaaC: Terraform.

    Моделирование/диаграммы: PlantUML, Structurizr, draw.io.

    Observability: Prometheus, Grafana, Jaeger.

    Безопасность: ознакомься с OWASP Top 10.

    Рекомендуемые книги и материалы (обязательные минимум)

    «Designing Data-Intensive Applications» — для данных и систем обработки.

    «Software Architecture in Practice» — принципы архитектуры.

    «Fundamentals of Software Architecture» — практические паттерны.

    Блоги: Martin Fowler, AWS Well-Architected (чтобы понимать cloud patterns). (Этого достаточно, чтобы не тратить время на тонны материалов — читать глубже по необходимости.)

    Книга: "Архитектура корпоративных программных приложений" М. Фаулера

    Курс: "System Design" на educative.io
